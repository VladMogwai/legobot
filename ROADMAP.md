# Roadmap

## Цель
По команде собирать фигурки из деталей, которые есть в Studio.
Вход: 3D-файл (потом — фото). Выход: файл модели, который открывается в Studio.

✅ 2. 3D-файл → кубики. Проверено на утке: узнаваема
✅ 3. Формат файла для Studio. Проверено: 4 кирпича импортировались, шаги и цвета пришли

## Размер и бюджет деталей (15.09)
Ориентир — модели на 300–500 деталей. Без флагов: `--parts 400`, единица — пластины:
втрое точнее по высоте, круглые формы (утка) читаются, кирпичи дают «кубик».
На 400 деталей пластины дают фигурку 7–10 см, кирпичи — 12–14 см. `--estimate` печатает
таблицу «цель по деталям → фактически деталей, Ш×Д×В в см, сколько 1×1» до сборки.
`--size СМ` / `--height СМ` — когда важен размер, `--unit bricks` — для угловатых вещей покрупнее.

Модель сплошная — проверено, что полая не экономит (утка, 15 штырьков, пластины):
сплошная 528 деталей; стенка 1 — 483, но 83 несвязанных куска и 272 штуки 1×1 (не собрать);
стенка 2 — 602 детали, больше сплошной. Число деталей задаёт поверхность, а не объём:
внутренность закрывается дешёвыми 2×8, а стенка требует мелочи.

## Скосы (15.09) — экспериментально, `--slopes`
Каталог 45°/33°/«сырок» ([slopes.py](legobot/slopes.py)), проверка геометрии `tools/check_slopes.py`,
скосы ставятся до укладки как занятые клетки (`fixed` в `layout_bricks`), рисуются в инструкциях.
Место выбирается по совпадению профиля скоса с объёмом меша (доли заполнения вокселей) и по
нормали меша. Замер на утке: пластины 528 → 541 деталей, кирпичи 483 → 483. Деталей не экономит:
скос заменяет 1–2 детали, но ломает крупные пластины рядом. Вид — спорный: на круглом теле
ступеньки смотрят во все стороны, и даже с фильтром по нормали скосы стоят островками.
По умолчанию выключено. Чтобы стало лучше, нужен другой принцип: подбирать детали к поверхности
меша целиком (fitting), а не к воксельным ступенькам.

## Каталог деталей (16.09)
`tools/catalog.py` → `catalog/parts.csv` (19 381 деталь с геометрией: номер LDraw и BrickLink,
название, категория Studio) и `catalog/part_colors.csv` (в каких цветах выпускалась — по
инвентарям Rebrickable, 6 164 детали). `legobot.catalog.exists(номер, цвет)`; после сборки
бот предупреждает о парах «деталь + цвет», которых не выпускалось. Выгрузки Rebrickable —
в `corpus/rebrickable/` (не в git).

## Проверка и настройки (16.09)
- `tests/` — эталонные тесты (`python -m pytest tests`): Марио с фото — сетка, набор цветов,
  точность цвета, связность стоячей фигурки. Прогонять перед коммитом любых правок сетки/цвета.
- Мозаика с фото пишет рядом `<имя>_check.png` (клетки фото | клетки LEGO) и печатает точность
  цвета: средняя ΔE, доля клеток с заметным отклонением, какие цвета дальше всего от фото.
- `legobot.toml` — вкусовые решения (чёрный контур, цвет задней стенки, ходовые/все цвета):
  бот их не угадывает.
- `--open` закрывает предыдущее окно Studio, открытое ботом: иначе легко смотреть на старую модель.

## Режим мозаики (14.09, прямой путь 16.09)
`--mosaic`: плоская пиксельная фигура → один пиксель = один тайл 1×1 на подложке из пластин.
С фото — **напрямую, без 3D** ([pixelart.py](legobot/pixelart.py)): фон вырезает rembg, по швам
между пикселями находятся два семейства прямых, их точки схода дают гомографию (перспектива
выправляется), шаг и фаза сетки — по автокорреляции градиента, цвет — медиана центра клетки,
чёрная боковая грань фигурки отбрасывается порогом яркости. Марио: 20×30, 436 деталей,
ошибок в клетках практически нет (через 3D было ~15 % ошибок). С 3D-файла — старый путь
(растр передней грани меша). Цвета: плоский подбор по всей палитре (`flat_codes`), 16 кластеров
со слиянием близких, тёмно-серый контур → чёрный; остатки — `--recolor`.
Сборка по умолчанию **стоячая** (`standing_bricks`): пиксель — кирпич, глубина 3 штырька:
2 пикселя + чёрная стенка сзади, граница чередуется по рядам (2+1/1+2), чтобы стенка и
пиксели связывались штырьками; та же стенка связывает разноцветных соседей по ряду
(подпорки не нужны — висящие детали держатся за штырьки сверху).
Глубина — `depth` в legobot.toml (4 штырька = 3.2 см, стоит на столе): чётные ряды 2+2, нечётные
1+3, где в стенке лежит «мост» глубиной 2 через границу — иначе пиксели и стенка не связаны.
Мосты кладутся первым проходом, стенка вторым, пиксели третьим. Шаги в файле модели = шаги PDF.
Марио: 327 кирпичей, 16×3.2×29 см, 66 шагов, один связный кусок. `--flat` — плоская мозаика из тайлов.

## Интеграции (14.09)
- **HF Space** (`--backend hf`): быстро, 1–2 модели в день на бесплатной квоте.
- **Kaggle** (`--backend kaggle`): TRELLIS.2 на T4, 30 GPU-часов в неделю. Запуск ≈ 20 мин сборка
  + 5 мин модель + ~50 мин разогрев Triton-ядер на первой генерации, дальше **~2 мин на модель**.
  Гонять пачками по 20–30 фото. Требует: аккаунт Kaggle с телефоном, токен `KAGGLE_TOKEN` в .env,
  принятые условия DINOv3 на HF, `HF_TOKEN` в .env (уезжает в приватный датасет — Secrets из API не читаются).
  Фон вырезается локально (rembg): модель фона у TRELLIS закрытая.
- Первый результат: Марио с фото — 6135 пластин, 9 цветов; утка — 1539 кирпичей.
- Следующее по интеграции: заморозить собранное окружение в датасет Kaggle → запуск за минуты.

## Потом, если понадобится
- Ограничение по своим деталям + список «докупить»
- Стёкла как детали (Windscreen из библиотеки): нужен источник области стекла —
  отдельный меш, сегментация фото или разметка
- Скосы и панели вместо ступенек: подбор наклонной детали под нормаль поверхности.
  Граница между «скульптура» и «набор»
- Ядро кирпичами, кожа пластинами: −40–50% деталей

## Что выяснили по ходу
- В LDraw «Brick 2 x 4» лежит длинной стороной вдоль X (3001: x ±40, z ±20). Перепутать — коллизии.
- Studio показывает детали шагов после выбранного прозрачными — это режим, не дефект.
- Полая оболочка в один кирпич на сетке 16 разваливается; полость — только с толстой стенкой.
- Stability в Studio ловит две разные вещи: clutch (мало штырьков) и stability (падает).
  Главный источник clutch — столбики мелких кирпичей на ступенчатом краю.

## Что уже решено
- Studio модель не строит, только показывает и проверяет. Строит наш код.
- Детали — только номера из библиотеки Studio (`/Applications/Studio 2.0/ldraw/parts/`).
- Новые .io — zip без пароля, внутри model.ldr с `0 STEP`.
